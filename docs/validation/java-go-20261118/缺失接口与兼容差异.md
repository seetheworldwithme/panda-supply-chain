### 3.2 原 Java 问题例外（Go 有意不复刻或仅复刻可观察行为）

1. **JAR 编译缺陷（6 个方法）**：`ChainAuthChatServiceImpl.loginPhone / loginChatPhone / loginChat / loginChatApp / noPhoneLogin / hasPhoneLogin` 入口即抛 `java.lang.Error: Unresolved compilation problems`（Feign `searchHasDefault(BusBusinessCard)` 缺 `JsonResult` 类型），HTTP 500/code 999。栈顶帧证据见本机 saas-auth 错误日志（loginPhone×16、loginChatPhone×12、loginChatApp×4、noPhoneLogin×2、loginChat×2、hasPhoneLogin×2）。Go 按源码意图实现正常行为并单独验收，**不记为两侧一致**。
2. **Cg/Xs `importOnce` 别名重复错位写入**：Java 先全量导入，再按 sheet 2–6 以错误实体二次读取导入。8 sheet 标准模板下实测：二次读取结算/流水/发票均校验失败（响应 errs 误报"失败 0"，掩盖首轮已成功写入），但销项发票 sheet 被当税收再写 1 条错位税收行（仅 month/system_code 等有值）。Go 不复刻二次写入，首轮落库与 Java 逐字段一致，响应保留 ImportResult 形状（errs/sucInfos/errInfos 与 Java 不同）。证据：`alias-once.json`。
3. **chain 字典两条 d_key/d_value 均 NULL 记录**：原 Java dictMap NPE，合同导入未解析即失败；未改原数据。Go 跳过异常记录。正向合同测试用本机 zjjg（无此问题），**不能据此宣称 chain 库全流程验收**。
4. **手机表单登录 SMS 旁路**：原 Java 关闭 SMS 校验且特定手机号有验证码旁路；Go 要求有效验证码，不复刻接管漏洞。
5. **`setAccount` 明文入库**：Go 使用既有 BCrypt。
6. **`updByOpenId` 缺失 openid 时全表更新风险**：Go 阻止。
7. **`"1".equals(Integer)` 恒 false 死分支**（selPhoneMsg etcName 恒 ""、reg 企业分支死代码）：属可观察行为，Go 已按原样复刻（等值比较不做类型转换）。
8. **`bus_business_card` 缺 msg_type/admin_phone 列**：原 Java feign findList 同样失败（两侧 500），属原库 schema 缺陷；Go 复刻失败语义，不擅自补列。
9. **payNotify 无金额/订单/幂等校验**：原 Java 仅 MD5 验签即改账单与会员；Go 与原实现一致（真实验签），**未新增校验**，列为原 Java 安全风险待产品决策，不视为 Go 缺陷。
