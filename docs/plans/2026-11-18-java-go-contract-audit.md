# Java → Go 接口兼容核查与修复计划

**Goal:** 以原 Java JAR 的实际路由、权限、输入与输出为契约，找出并修复 Go 迁移差异，避免前端切换报错。
**Architecture:** 原 Java 源码及本机 JAR 运行实例只读对照；Go 路由使用实际 ServeMux 离线匹配，避免探测写接口污染数据。响应对比覆盖 HTTP 状态、JSON 类型、缺失键、null、数组顺序、分页及附件；写入仅使用本机隔离 fixture 并清理。
**Tech Stack:** Go net/http/testing、Python unittest/urllib、Java Spring、MySQL。

1. 核对分支与未提交修改；保留未跟踪 AGENTS.md，不提交、不推送、不部署。
2. 从七个业务服务控制器提取完整 method/path 清单；核对运行 JAR 映射与源码映射，未核实的来源明确标记。将完整接口清单和缺失表写入 docs/validation/java-go-20261118/。
3. 用 Go 真实路由注册作离线匹配，覆盖动态路径与请求方法；不通过调用 add/delete/payment 等接口判断路由存在。
4. 审阅既有对比脚本，补全认证、组织、合同等缺失测试矩阵。使用本机平台、企业账号，严格比较 JSON 与 HTTP 状态；响应正文仅保存脱敏摘要，令牌不落仓库。
5. 按差异逐项追查 Java 控制器、服务、Mapper、序列化；先写失败用例，观察失败后修复 Go，再跑相关回归。
6. 缺失接口先登记到清单再实现。Excel 比较解码后的工作表内容与响应头，不比较 ZIP 时间戳；写接口比较响应及数据库副作用。
7. go test ./...、go vet ./...、只读接口对比及隔离写入断言。报告精确通过数、失败数、未覆盖与硬性外部依赖，不以路由存在或双方报错代替功能完成。

验收限制：本机现有 Java 8765、Go 8799；不得修改远端服务、正式业务数据或原 Java 源树。凭据由进程环境或用户指定私密文件输入，不读取整份凭据文件排查普通问题。
